## Findability: the canonical address, the card, robots and the sitemap (2026-10-19)

**Decision.** COMMON-PROJECT-SPEC C17 (J1, J3 of the catalog) applied: `index.html` carries the canonical address and the OpenGraph and Twitter tags; `public/robots.txt` allows everything and names the AI-crawler families in a comment — the owner's policy across his sites is to ALLOW them, training and answering alike, and `steevepommier.com`'s file is the model; `public/sitemap.xml` lists the home alone, since every other screen is a hash route (`#/develop`, `#/legal`) of that one page. **The tags are ABSOLUTE on purpose**, the one exception to the base-path rule of `deployment.md`: a canonical is a full address by definition, OpenGraph wants a full URL for its picture, and Vite rewrites the `href`/`src` of assets with the base, never a `<meta content>` — so a `/atelier/` preview still names the live card, which is right, a crawler only ever reading the deployed page. The host is therefore written in FOUR places — the head, `robots.txt`, `sitemap.xml` and `SITE_URL` (`src/app/site.ts`, built from `DEPLOYED_ORIGINS`) — and `src/app/site.test.ts` holds them together, with the title and description held to the manifest's and the card's size read from its PNG header. **How to apply**: a new fact of the head is one more line of that test, never a copy somewhere the test does not read; a new page of its own (there is none: the screens are routes) would be a second `<url>` of the sitemap.

**The card is drawn by `scripts/gen-social-card.mjs` and COMMITTED** (`public/social-card.png`, 1200 × 630), a generator of the `gen-icons.mjs` shape: `npm i --no-save sharp` (never a dependency), `node scripts/gen-social-card.mjs`, commit the PNG. It composes the mark rasterised from `public/icons/icon.svg` — the mark's one drawing, never re-traced — with the wordmark in the suite's own faces, on flat paper (no gradient: the owner sees banding). **Trap, measured**: sharp's librsvg finds fonts through fontconfig and found none of the repo's — the `@fontsource` packages ship WOFF/WOFF2 only, which the bundled FreeType does not open — so every face silently fell back to a system sans (Inter here). A WOFF is an sfnt whose tables are zlib-compressed: the script unwraps the three faces it uses into TTFs in a temp folder, writes a `fonts.conf` naming that folder alone, and sets `FONTCONFIG_FILE` BEFORE importing sharp — a dynamic `import()`, since a static one is hoisted above the assignment. Nothing of that is committed. **How to apply**: a redesigned card takes a NEW file name, changed here and in `index.html` together, because every platform caches on the URL (versus' rule for its icons and cards); a new face on the card is one more `FONTS` entry.
