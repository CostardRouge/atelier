## Planned draws only Atelier's posts (2026-11-12)

His ask («filter posts by atelier app in the planned zone»): his Sketchbook (`CostardRouge/p5-templates`, `local-first.md`) posts through the same Postiz, and Planned showed its posts. **How a post is known as Atelier's** (`atelierPosts`, `recap-planned.ts`, pure): the tag `Atelier` (`ATELIER_TAG`, `client.ts`), OR a recap of this device keeps it in `publish.publications` (older sends, other devices' tags missing), OR it shares a Postiz `group` with one of those. **Why a tag**: read in Postiz's code that day — `POST /posts` `tags: [{ value, label }]` is linked BY NAME to a tag that already EXISTS (an unknown one is dropped silently, no error), the public API has no route to create one, and `GET /posts` returns `group` and `tags` (`[{ tag: { name } }]`) though its docs list neither; `group` is generated server-side (`keepGroup` false on create), so it cannot carry a mark. **So he must create a tag named «Atelier» once in his Postiz** — until then only this device's publications identify Atelier's posts. `postBody` tags every post, so the panel and `recap.schedule` (one `sendPosts`) are both marked. **Every post still counts**: `weekStrip`'s free slots and a day's `busy` read ALL posts (a Sketchbook post on Sunday leaves Sunday with no free slot), and `slotsWithState` / `postMoments` / the panel's When are untouched. The section says so quietly: `HIDDEN_NOTE` as the peek's tooltip and, under the strip, «N posts from other apps hidden · they still take their slots» for the week shown (`hiddenInWeek`). **`recap.calendar` chose the same**: its `weeks` list Atelier's posts with `otherApps` per week; `nextSlots` count everything.
