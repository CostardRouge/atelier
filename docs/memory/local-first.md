# Local-first — the network, the filesystem, persistence

Read before adding anything that could touch the network, read files, or persist data. This is the project's defining constraint, not a preference.

## Nothing is uploaded, ever (2026-08-20)

**Decision.** Files are read in the browser through `File` handles and processed locally; there is no backend, no account, and no telemetry. Even the `ErrorBoundary` only logs to the console. **Why**: it is the product's whole premise (README, first paragraph) — the user's footage is private and often huge. **How to apply**: any proposal that sends bytes, filenames, or error reports off the machine is out of scope by default; if it seems unavoidable, ask the maintainer rather than implementing it.

## The network calls that *do* exist, and their status (2026-08-20)

**Fact**, traceable in the code — worth knowing before claiming "the app makes no requests":

- **OpenStreetMap raster tiles** (`tile.openstreetmap.org`; the URL and `setTiles` live in `shared/map/track-map.ts`, called by `map/use-flight-map.ts`, `composer/use-composer-map.ts`, `composer/export-composition.ts` and, since 2026-09-28, Trips' big picking map `roadtrip/StopsMapSheet.tsx` — a third SURFACE of this one exception, not a new exception: off at every first open, worded by `TILES_TOGGLE` (whose hint became generic that day, "Everything drawn over it works offline", since "the flight path" was wrong on the new surface), remembered in module state for the tab only, never in `localStorage` nor on a document, and never painted into an export — the openers still draw their own paper). **Revised the same day by his ask** (*«option to have the map texture loaded in the animation … in the export, and the preview as well»*): tiles ARE drawn into an Itinerary or a Virée when the PIECE asks (`MapOptions.basemap`, `DriveGround 'tiles'` — options, on the document) AND this DEVICE allows it (`atelier.map.tilesInOpeners` in `localStorage`, `shared/map/osm-tiles.ts`, turned on by the gesture that turns the background on, with the notice in view; a trip opened on another device or from someone's backup fetches nothing and says so with an «Allow on this device» button). The variant only DECLARES the region (`HookVariant.wantsBasemap`); the shell fetches (at most 64 tiles a region, and under a following camera — Virée's or the Itinerary's — a zoom PYRAMID of one-tile rasters along the road, each frame at its own zoom, within `stripBudget()` — 512 tiles on a computer, 96 on a phone, `tile-strip.ts`, rev. 2026-10-07 —, four connections at most, a tile timing out at 20 s and falling back to its parent; blobs cached for the TAB, never on disk — a cache that outlives the tab is his call; OSM's tile policy forbids bulk downloading, which is why the pyramid is bounded by the frames the camera really shows) and puts the raster in `ctx.pictures`, so the stage, the rail, the PNG deck and both video paths carry it; every frame the tiles are in paints «© OpenStreetMap contributors» (the licence's condition, not a style). The export therefore depends on the tile server being reachable at render time — it AWAITS every tile it will draw before its first frame (since 2026-10-07), a coarser level stands in for one that failed and the delivery says how many: an unreachable server is a sentence in the panel and the paper stands in — the documented exception: off by default, opt-in per session, and it reveals the viewed area to the tile server. The flight path itself always draws on a tiles-free style. **Every map surface defaults OFF, not only the first one (2026-09-28)**: the Composer shipped with its toggle ON, so opening it contacted the tile server while the README and this file said "off by default" — the default lived in each tool's `useState`, and the second surface copied the wrong value. **How to apply**: a new surface offering tiles starts `false` and words its toggle from `TILES_TOGGLE` in `track-map.ts` (the label and the hint naming what is revealed), so the wording cannot drift either; its export takes the preview's choice, never its own.
- **ffmpeg.wasm core** (`unpkg.com/@ffmpeg/core`, pinned version, in `shared/media/transcode.ts`) — ~31 MB fetched on first transcode only, then browser-cached. Opt-in per clip.
- **Fonts are OURS since 2026-09-24** (his call: "chargeons les polices google en local"). Google Fonts used to be fetched on every page load, unconditionally, and no callout named it. The four faces now come from `@fontsource/*` packages imported in `main.tsx` — exactly the weights the old link asked for — and Vite ships their woff2 in `dist/assets`, each `@font-face` scoped by `unicode-range` so a page fetches only the subsets it draws. Measured: a page load contacts `127.0.0.1` alone. **How to apply**: a new face or weight is a new `@fontsource` import, never a `<link>` to a CDN; `overlay/fonts.ts` still `document.fonts.load`s a face before a canvas measures with it.
- **An OpenStreetMap map link** built by `exif/exif-format.ts` for a photo's GPS position — a plain `href`, opened only when the user clicks it.
- **OpenStreetMap place search** (`nominatim.openstreetmap.org/search`, in `shared/map/geocode.ts`, since 2026-09-03) — Road Trip looking a stage's place up by name. The maintainer's explicit product call, taken knowing it widened the README callout from one exception to two. It is the first request that carries **text the user wrote**, so the guard rails are tighter than the tiles': off until turned on (`shared/map/use-place-search-pref.ts`, a `localStorage` flag, never on the trip document — exporting a `.roadtrip.json` must not mail someone else's consent), a notice naming what will be sent before the first search, and **no search-as-you-type** — Enter or the button, one gesture one request, which is also the polite reading of Nominatim's 1 req/s cap given a browser cannot send an identifying `User-Agent`. Only the query leaves; no photo, no position we already hold, no trip. Typing a place by hand stays fully sufficient, which is what keeps the feature a convenience. Since 2026-10-02 the request adds `addressdetails=1`: the same words leave, the answer carries the structured address (county, state, ISO code, country) the place now keeps — `roadtrip.md`.

- **A connected Winnow instance** (`shared/sources/winnow/client.ts`, since 2026-09-01) — the media source the maintainer runs himself. Only ever the base URL the user confirmed on `#/connect`; nothing at boot; the session is Winnow's own cookie (same-site), no credential stored here. Requests: capabilities on connect, a calendar per month, a day's rows, the timeline's chapters (2026-09-06), then the bytes of what the user picked. **One more since 2026-09-06**: opening a Road Trip piece whose picture the library no longer holds re-fetches it from the instance its ref names (`resolve-media.ts`); since 2026-09-16 an open Develop roll does the same for its open picture and two neighbours each side, into a pool of its own and never into the library (`develop-media.md`). Still never at boot, still only a host already allowed — and it is what lets a reload be answered without ever storing media bytes. See `architecture.md`, «Remote sources» and «A remote ref is re-FETCHED, never cached».
- **The first WRITE, since 2026-09-06: finals sent back to that same Winnow** (`POST /api/upload` + `POST /api/reconcile`, `tools/studio/SendFinalsPanel.tsx` over `sources/winnow/finals.ts`). Offered only after an export whose source media came from a connected instance, only to THAT instance, only the files just rendered; one click, never automatic; the panel names every file and its weight before anything moves, and refuses up front on a read-only account (`canWriteBack`), a clip from another instance, or a file over `limits.maxUploadBytes`. The README's Winnow section says "fetches from it, and uploads to it on that one button". **This is what "your media never leaves machines you own" now means**: a Winnow is the user's own server. Anything that would send to a third party is still out of scope by default.
- **The HEIF and JPEG XL decoders** (`shared/media/wasm-still.ts`, since 2026-09-26) — a JS chunk and a `.wasm` in `dist/`, from our OWN origin, requested only the first time the browser refuses a `.heic`/`.hif`/`.jxl`. Not a third party; listed because it is a request (~2 MB each).
- **`public/geo/cities.json`**, the committed GeoNames index (6.5 MB, 2.6 MB over the wire), fetched from our OWN origin through `import.meta.env.BASE_URL` — so it is not a third party and changes no promise, but it IS a request and belongs on this list. Read **only when a deduced Road Trip leg needs naming, when a Develop export writes a place name** (M4, 2026-09-23 — once per run, only when the roll's *Place name* group is on), **or when Trips' big picking map opens** (2026-09-28 — its towns ARE its offline basemap, handed to MapLibre a view at a time), never at boot (`roadtrip.md`, `deployment.md`). The same shape as `public/models` (the segmentation model, ~17 MB, loaded only when a subject mask is asked for) and, since 2026-09-20, `public/lut-thumbs/` (~140 KB of picker tiles, read when the look gallery first opens). **How to apply**: an asset we ship is still a fetch — state it here, keep it off the boot path, and never move one to a CDN.
- **`public/geo/land.json`**, Natural Earth's land outline (459 kB, 174 kB over the wire, since 2026-09-29), from our OWN origin through `BASE_URL`, read only when a trip's MAP view first opens — the drawn coastline under it, so that view needs no tile server (`deployment.md`, `roadtrip.md`).
- **A pack look's LATTICE, from a connected Winnow's file store** (`shared/lut/pack-remote.ts`, since 2026-09-20) — the THIRD write target as well as a read (see the bullet below and `docs/lut-packs.md` §4.4). `GET /api/apps/atelier/files/<sha256>` when a picture asks for a look this device does not hold, one look at a time, never because a list was opened; `PUT` when the author presses "Keep on <instance>". The bytes are the user's own purchased `.cube`, going to the user's own server, under their own account — never a third party, and never automatic. What comes back is cached in IndexedDB, which is the ONE deliberate exception to «a remote ref is re-FETCHED, never cached» (`architecture.md`): a picture is big, one-off and already addressed by its document, while a look is small, few, reused on every picture, and a phone without it cannot grade offline (`docs/lut-packs.md` §4.2).
- **A Road Trip or a Studio project kept on a connected Winnow** (`shared/roadtrip/trip-remote.ts`, `shared/projects/project-remote.ts`, since 2026-09-06) — the second WRITE, beside the finals above, and only when the author picked that instance on the "Keep on" picker (creation, import, move). What travels is the document (a trip's place names, dates, badge copy; a project's overlays, look, export matrix; media refs by hash — never a picture, never a thumbnail, never a folder handle), under the user's own account there (`/api/apps/atelier/docs`), pushed after ~5 s idle, on tab hide, on leaving the trip and on "Save now"; opening the document reads it back with `If-None-Match`, and each gallery lists what the account keeps there. A document kept locally makes no request at all. Stated in the README's Sources section and its network callout. Design and limits: `docs/roadtrip-persistence.md`.
- **A language model reading a picture — PROPOSED 2026-10-02, NOT decided** (`docs/auto-develop.md` §7). The assistant he asked about (Claude, his own key) would send a REDUCED proxy of a photograph, its histogram and EXIF to Anthropic and get a `DevelopSettings` back: a FOURTH third-party exception, and the first that would carry a picture. If he says yes it follows the Nominatim conventions exactly — opt-in, off by default, a `localStorage` consent never on a document, the key in `localStorage` or relayed by his Winnow (his call), never the RAW, named in the README's callout with what leaves and to whom. Until he says so, nothing in the suite calls a language model. The local alternatives (`auto-develop.ts`'s verbs, a model learned on his rolls and served from our origin like the segmenter) change nothing here.

**Atelier writes to a Winnow in THREE places now, not two** (2026-09-20): finals going home, a document (trip, project — and a LUT pack's index), and the file store a pack's lattices live in. The ruling underneath is unchanged and is what keeps the list short: only to an instance the user named, only on the user's own gesture, never to a third party and never automatically.

- **Lensfun lens profiles** (`raw.githubusercontent.com/lensfun/lensfun/master/data/db/<file>.xml`, in `shared/lens/lensfun-source.ts`, since 2026-09-23) — his YES of the Lightroom audit (§8, item 20): fetched ON DEMAND per lens, KEPT locally, never the whole database in `dist/`. Opt-in by a `localStorage` flag (`atelier.lensfun`, never on a roll), asked for from the Lens section. The request carries NO data of ours — it names a maker's file (the camera maker's first, the independent lens makers' for that kind of body only when the lens is not there) — and what is kept (`atelier-lens-profiles` in IndexedDB) is the matched camera and lens, never a file. The profile resolved for a picture is stored ON the picture, so an export and a second device need no request.

**How to apply**: adding another is a product decision, not an implementation detail. Anything new must be opt-in, off by default, and stated plainly in the UI and the README. Two conventions the place search set, worth copying: a third-party URL belongs in `shared/map/` beside `track-map.ts` (one folder to audit, rather than a URL buried wherever it is used), and a consent flag lives in `localStorage`, never in a document that can be exported. The promise this preserves is now "your media never leaves machines you own": a Winnow is the user's own server, and Atelier never talks to one it was not given.


## Three file-access paths, one internal shape (2026-08-20)

**Decision.** `shared/sources/file-sources.ts` is declared the **only** brick that changes for a native shell: the Chromium `showDirectoryPicker`, the `<input webkitdirectory>` fallback (Firefox/Safari), the plain multi-file picker and drag-and-drop all converge on `Promise<File[]>`. **Why**: the rest of the pipeline should not know where files came from, so a Tauri build swaps one module. **How to apply**: keep new access paths behind the same shape; capability detection (`showDirectoryPicker` present?) belongs there, not in components. Writing back to disk uses the same File System Access capability check in `shared/sources/write-files.ts` (`pickWritableDirectory`, salvaged from the retired Cull tool for the studio's export-to-folder path).

## Persistence is deliberately minimal (2026-08-20)

**Decision (rev. 2026-08-21; 2026-09-16: a Develop roll keeps the directory handles its local pictures came from, the same way, AND — the one exception to "media bytes are never persisted", the maintainer's choice — a 2048 px working preview of each of its local pictures when that roll asks for them, deleted when it stops; never for an instance's picture — `develop-media.md`).** **(rev. 2026-10-07: a FOURTH case — each roll picture AS SHOT, a 256 px vignette with its stats and camera facts in `atelier-develop`'s `shots` store, the pair a model learns a develop from; kept by DEFAULT on every device, switched in Develop's settings → Learning, where Off clears the store; never a position, never a word; read into one file only by the gallery's own verb — `develop-roll.md`, «Each picture AS SHOT is kept beside its record».)** **(rev. 2026-09-20: a THIRD IndexedDB database, `atelier-lut-packs`, holds the LUT vault — each pack's index and each look's lattice as 16-bit binary keyed by the source file's SHA-256, `shared/lut/pack-store.ts`. It is the deliberate counter-case to the rule above it: a LUT is not media, it is small, few and reused on every picture, and a device without it cannot grade at all. An UPLOADED `.cube` goes here too since step 7 of `docs/lut-packs.md`, which is what stopped documents inlining lattices. Winnow is the truth and this is a cache — iOS Safari erases a site's script-written storage after 7 days unused — so a miss is re-fetched silently and `navigator.storage.persist()` is asked for once.)** Two stores existed before that: `localStorage` for UI prefs (sidebar collapse flag, the LUT interpolation mode, the ★ favourites shortlist), and IndexedDB (`atelier-studio`) for studio project documents — including directory *handles* (structured-cloneable, unlike `File`s) and baked thumbnails. Media bytes are never persisted anywhere. **Why**: `File` handles cannot survive a reload; directory handles can, turning project reopen into one permission click. **How to apply**: storage failures must degrade silently to in-memory (the store already returns `[]`/false instead of throwing); `navigator.storage.persist()` is requested once per studio session; details in `studio.md`.

## A future native shell is an accepted direction, not a plan (2026-08-20)

**Fact.** The README states a future Tauri app would bundle ffmpeg for guaranteed decoding and real thumbnails, and the code is arranged for it (DOM-free logic, one file-access brick). Nothing is scheduled. **How to apply**: keep the arrangement; do not start the native shell without asking.

## A document is UNTRUSTED input, wherever it comes from (2026-10-02)

**Decision.** A stored, imported or pulled document — a trip, a roll, a pack index, a `.cube` carried inside one as `customText` — is read the way a network answer is: an id written into an HTML string is escaped (`TripMapView.tsx`'s `esc` on EVERY interpolation; the one line that forgot was a stored XSS a `.roadtrip.json` could plant), a parser bounds what it allocates BEFORE it allocates (`parseCube`: a size under 2 or over `MAX_CUBE_SIZE` = 129 refused, and a text with fewer lines than the table has rows refused first — a 30-byte file used to ask for 800 MB), and a link is kept only when `webUrl` says http(s) (`lut-pack.ts`, on read and on build). **Why.** `docs/audit-2026-10-02.md`, SEC-01/02/03/07. **How to apply.** A new field on a document is read by a `read*` function that drops what does not fit (`readCarSpec` is the model); the trip's stages and posts still ride a type cast (SEC-02) and are the next to convert; an `innerHTML` string takes `esc()` on every value, or is built with `createElementNS`.
