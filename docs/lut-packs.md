## 1. The ask

The maintainer bought a LUT pack from a YouTuber. It is split into
categories (conversion, creative, one-click) and, inside them, per camera —
many files, most of which he will not use. He wants:

1. The pack **selectable in the existing look pickers**, under the
   **author's name**, with its categories as **nested sub-sections**.
2. Usable on **his Mac and his iPhone**, under one account.
3. **Never public.** He paid for a licence to use the looks, not to
   redistribute them; putting them on the deployed site "would really not be
   ethical". Graded exports are what the licence is for and are fine; the
   `.cube` itself stays private.
4. (Done in passing, see §8.1) the flat "Add a look" list in the Develop /
   Grade panel grouped with native `<optgroup>`s like the other pages.

Context he gave, to weigh migrations and compatibility accordingly: Atelier
is a proof of concept a few months old, with **one user** (him); nobody else
knows it exists.

## 3. The hard rules (the maintainer's, not negotiable)

1. **A document carries a REFERENCE, never a lattice.** A trip, project or roll
   layer that uses a pack look stores pack id + look id + content hash
   (~200 bytes). Never the `.cube` text. The reason is *weight* as much as the
   licence: "5–7 MB per look, fifteen-odd looks — it would make a road trip
   unbearably heavy; the vault must be decoupled, apart".
2. **Never resample a purchased look.** 65³ stays 65³. The 33³ idea (to fit
   Winnow's JSON cap) was rejected: "I don't want the author's look modified".
   Only the *encoding* changes (text → 16-bit binary), which is invisible (§4.3).
3. **Nothing of a pack in `public/` or in git** — not the `.cube`, not its
   thumbnails. `public/` is deployed to GitHub Pages and the repo is public.
   The vault must never be a folder the `virtual:luts` plugin scans.
4. **Nothing of a pack in a file he shares.** `.roadtrip.json`,
   `.atelier.json`, a roll file and `house-style.json` carry references only.

### 3.1 The leak this rule closes — it exists TODAY

"Upload .cube" (`GradePanel` → `stack.addCustom()`) keeps the whole lattice as
the layer's `customText` (`use-lut-stack.ts`, `project-types.ts`,
`roll-types.ts`), so it rides every trip/project/roll export file and every
Winnow document sync. Only the house style filters it out (`isUploadedLook`,
`saved-grade.ts`). **Agreed fix**: "Upload .cube" writes into the vault too
(§9, step 7). **Nothing to migrate**: the maintainer confirmed no existing trip
holds a purchased lattice.

## 4. Storage — Winnow doc bucket (index) + Winnow file store (bytes) + local cache

The maintainer chose "option 1" (Winnow) and asked for "a combination of Winnow
storage, the bucket and local". The measurement turned option 1 into 1 + 2:

| Where | What | Why |
|---|---|---|
| **Winnow document bucket**, new kind `lutpack` | the pack INDEX: author, name, link, the tree, each look's label/node/size/hash, **its baked thumbnail(s)**, the hidden list | small JSON; reuses etag / `If-Match` / 412 / "your rows only, others 404" that trips already rely on |
| **Winnow file store** (NEW route) | each look's lattice, 16-bit binary, **keyed by SHA-256 of the source file**, immutable | none of the 25 looks fits the bucket's `MAX_DOC_BYTES` (1 MiB): 1.65 MB binary, 2.2 MB as base64. Any size; immutable by hash = cache forever, free dedupe; the Overlays could live there later |
| **Local cache**, IndexedDB on each device | each lattice fetched on first use | the phone grades offline; nothing is recomputed |

### 4.1 Why not the alternatives

- **Raise the bucket's cap for one kind**: 2.2 MB of base64 per read, a JSON
  path for bytes, and a dead end for the 140 MB overlays.
- **Resample to 33³ to fit**: changes the author's look — rejected (§3, rule 2).
- **Local only, per device**: import again on every device — and twice on an
  iPhone (Safari and the home-screen app have separate storage); a look added
  on the Mac never reaches the phone.
- **Private build / dev-server folder**: phone only on the LAN, never on the
  deployed site; one misconfigured scan ships the pack to GitHub Pages.

### 4.2 The cache is never the truth

iOS Safari erases script-written storage of a site unused for 7 days (the
home-screen app is exempt; Atelier launches standalone from its icon, see
`frontend.md`). So **Winnow is the truth, the cache is a cache**: a look
missing from IndexedDB is fetched again, silently. Ask
`navigator.storage.persist()` once.

This is the **opposite case of the suite's "never cache a picture's bytes"
rule** (`architecture.md`): a picture is big, one-off and already addressed by
its document; a look is small, few, reused on every picture, and a phone
without it cannot grade offline. Record it as its own decision when built.

### 4.3 Encoding

- Parse the `.cube` once at import (`shared/lib/cube-parser.ts`, pure), store
  the lattice as **16-bit** (float16, or unorm16 over the declared
  `DOMAIN_MIN/MAX` — both 1.65 MB for 65³). Precision: float16 ≈ 1/2048
  relative; one 8-bit output step is 1/255 — ~8× coarser, so invisible.
  Keep the domain and the size in a tiny header.
- The **hash is SHA-256 of the SOURCE file bytes** via `crypto.subtle.digest`
  (~10 ms on a Mac, ~50 ms on a phone for 6 MB — about 1 s for the whole
  pack, once at import). Never the file NAME (a rename or an author's v2 under
  the same name would lie). Never MD5 (WebCrypto has none).
- Re-importing the same files recognises them by hash: nothing is uploaded or
  re-baked twice.

### 4.4 Winnow's side (a PR in `~/Documents/GitHub/winnow`, `CostardRouge/winnow`)

- `src/lib/appDocuments.ts`: add `"lutpack"` to `DOC_KINDS` (today
  `["trip", "project", "roll", "presets"]`); the 1 MiB cap stays — the index
  is small. Advertise it in `GET /api/capabilities` like the other kinds.
- **New: a per-user file store for a client app** — a migration, then
  `PUT` / `GET` / `DELETE /api/apps/:app/files/:sha256`:
  - scoped to the signed-in user, any role (a viewer owns its pack like its
    trips); a row that is not the caller's answers **404**, never 403;
  - `PUT` verifies the body's SHA-256 equals the path (refuses otherwise),
    has its own cap (say 16 MiB — room for a 65³ look; decide for the
    overlays later) and a per-user quota;
  - `GET` answers `Cache-Control: private, max-age=31536000, immutable`,
    **never** a public or shared cache, and CORS like the docs routes;
  - stored where the instance's storage driver keeps its derivatives (read
    Winnow's storage driver before choosing the path);
  - `DELETE` is the client's call: deleting a pack deletes its files.
- This makes Atelier write to Winnow in **three** places instead of two
  (finals home, documents, now files). Update the "Atelier writes to a Winnow
  in two places only" bullet in `MEMORY.md` and `local-first.md` when built.
- Local test recipe for the pair (two localhosts are same-site):
  `docs/memory/testing.md`.

## 5. The model

### 5.1 The pack index (`lutpack` document)

```jsonc
{
  "id": "pk_<uuid>",                 // minted at import
  "name": "AUTHENTIC",
  "author": "Victor Jimenes",
  "url": "https://victorjim.gumroad.com/l/authentic_lut",
  "tree": [
    { "id": "conversion", "label": "Conversion", "children": [
        { "id": "dji", "label": "DJI", "hint": "D-Log, not D-Log M" }, … ] },
    { "id": "creative",   "label": "Creative" },                  // no camera level
    { "id": "one-click",  "label": "One Click", "children": [ … ] }
  ],
  "looks": [
    { "id": "one-click/dji/d-log",          // from the path, stable
      "label": "D-Log",                      // cleaned (§5.3)
      "node": "one-click/dji",
      "file": "One Click LUT/DJI/AUTHENTIC_LUT_D-LOG.cube",
      "size": 65,
      "hash": "sha256:…",                    // = the file store key
      "thumbs": { "log": "<small webp, base64>", "rec709": "<…>" } },
    …
  ],
  "hidden": ["one-click/samsung"]            // "only what I keep"
}
```

The whole index with 25 looks × two ~6–8 KB thumbnails stays well under the
1 MiB cap. Thumbnails travel WITH the index: the iPhone gets them when it
reads the pack, with nothing to compute or download beyond it.

### 5.2 A layer that uses a pack look

```jsonc
{ "id": "…", "source": "pack",
  "pack": "pk_…", "look": "one-click/dji/d-log", "hash": "sha256:…",
  "name": "AUTHENTIC · One Click · DJI · D-Log",
  "intensity": 1, "enabled": true,
  "customText": null }                        // never the lattice
```

- `gradeKey` (`saved-grade.ts`) must include `pack`, `look` and `hash` so two
  looks never share a baked cube.
- `restore-grade.ts` resolves `source: 'pack'` through the vault
  (cache → file store), like `loadBuiltinLut` for built-ins.
- **On a device without the pack**, or in a trip opened by someone else: the
  layer STAYS in the stack, says "not in this browser's vault" (and why:
  not connected / not imported), and renders bypassed. Never dropped
  silently — the suite's rule that a preview shows the real value or nothing.
- **An author's update** (same path, new hash): the reference keeps its hash;
  keep the old file while a document uses it, and say "updated since" with a
  verb to switch. (Decide the exact UI when building; nothing is lost either way.)

### 5.3 Import cleans the names

- One camera vocabulary: `APPLE`/`Apple` → Apple, `INSTA360` → Insta360,
  `BLACKMAGIC` → Blackmagic, `FUJIFILM` → Fujifilm, etc.
- Look labels without the pack prefix and the brand already given by the
  node: `AUTHENTIC_LUT_S-LOG3_S-GAMUT3.CINE` → "S-Log3 · S-Gamut3.Cine",
  `AUTHENTIC_LUT_I-LOG(CHAUD)` → "I-Log · warm", `CANON_CLOG3` → "C-Log3".
- The tree's depth varies (Creative has no camera level): the model and the
  picker must not assume three levels.
- Import shows the parsed tree before anything is written, lets him rename
  and hide, and only then uploads.

## 7. Thumbnails — baked once, live only on request

The maintainer's own proposal, agreed: today the gallery re-parses every
lattice and re-bakes every tile **on each open**, on a synthetic chart that
never changes — the same pixels recomputed forever; for this pack on a phone
that would be ~150 MB of text parsed to draw a grid. Instead:

| Looks | When the thumbnail is baked | Where it lives |
|---|---|---|
| Built-ins (`public/luts/`, Film stocks) | at **build** time, from the two references in `public/reference/` | shipped as small images in the build |
| A pack | at **import**, on the Mac, once | in the pack index on Winnow — **never in `public/`** |
| "On my picture" | live, as today | only when the author explicitly asks |

- Feasible because the baking code is already pure and DOM-free
  (`lut-preview.ts` → `bakeLutPreview`, `interpolate.ts`, `cube-parser.ts`;
  the film stocks' `filmCubeFor` likewise): a Vite plugin runs it in Node at
  build, like `virtual:luts`. Encoding an image in Node needs no new
  dependency beyond a tiny PNG writer over `zlib`, or ship raw RGB.
- **The log-input trap** (true today too): a conversion or one-click LUT
  expects LOG input; on a display-referred image — the synthetic chart
  included — it previews wrong (over-contrasted, over-saturated). So the
  reference is a **PAIR**: a **log frame** (one of his D-Log M rushes) for
  log looks, a **Rec.709 photo** for creative ones; each look is tagged
  log/rec709 (from its category: Conversion and One Click = log, Creative =
  rec709). Recommended over the alternative — one Rec.709 image re-encoded
  per camera through each published log curve — because `transfer.ts` has no
  log curves yet and DJI does not publish D-Log M's, so his own camera would
  still need a real frame.
- **Weighed and declined** (the maintainer's idea, confirmed 2026-09-19):
  baking a pack's thumbnails on the dev server and committing them to
  `public/` keyed by hash, so any device with the files finds them ready. The
  plan already gives that — baked once at import, synced with the index, the
  hash already the file store's key — while the dev path works only on his
  machine, proves nothing about the deployed app, and blurs the one simple
  line of §3, rule 3.
- **The two references are IN the repo** (2026-09-20), both the maintainer's own
  pictures, so nothing here waits any more:
  `public/reference/reference-dlogm.jpg` — a frame at 26 s of a Mini 4 Pro
  D-Log M clip (10-bit HEVC, 900×1600), water, rock, vegetation, a grey roof
  as a near-neutral, sand and shadows; and `public/reference/reference-rec709.jpg`
  — a Mini 4 Pro JPEG (1600×900), a headland with surf, foliage and pale rock.
  **A look's reference is chosen by its family**: Conversion and One Click read
  the D-Log M frame, Creative and the built-in creative looks the Rec.709 one.
  The D-Log M frame was CONFIRMED to be log by applying
  `public/luts/dji/dji_mini_4_pro_d-log_m-to-rec709.cube` to it and seeing a
  natural picture come out — the honest test, since D-Log M is a MILD log that
  does not look as washed out as D-Log, and a drone's JPEG or DNG is never log
  (D-Log M is a video profile; a DNG's embedded render is display-referred).
